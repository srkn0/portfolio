## Starting point

Minimal, distroless or slim images often ship without debug tooling. `dig`, `nslookup`, `curl`, `netcat` and `ping` are frequently absent. The following sections collect shell-native means that work without any extra installation.

## Detect available tools

Before any debugging, check which commands are present at all.

```bash
command -v dig nslookup curl wget nc getent
```

`command -v` is a shell builtin and available in every POSIX shell. It prints only the paths it finds and skips missing commands. The exit code indicates whether all requested commands exist.

## DNS resolution without dig

When `dig` and `nslookup` are missing, `getent` resolves a hostname through the C library's name service switch.

```bash
getent hosts service.example.com
```

The output contains the resolved IP address and the name. Resolution follows the configuration in `/etc/nsswitch.conf` and `/etc/resolv.conf`, the same path that regular application calls take.

Limitation: `getent` belongs to glibc. In images based on musl (Alpine) or BusyBox it is absent, as it is in fully distroless images without a shell.

## TCP connection without netcat

Bash provides a virtual file `/dev/tcp/host/port` through which a TCP connection can be opened.

```bash
(exec 3<>/dev/tcp/service.example.com/443) && echo open || echo closed
```

The call opens file descriptor 3 as a bidirectional TCP connection. If the connection succeeds, the port is reachable. This performs a port check without `netcat`.

Limitation: `/dev/tcp` is a Bash extension. It is not available in `sh`, `dash` or BusyBox `ash`.

## Read a process environment

The `/proc` pseudo filesystem exposes each process's environment variables under `environ`.

```bash
tr '\0' '\n' < /proc/1/environ
```

The variables are separated by null bytes; `tr` replaces them with newlines. This inspects the configuration of a container's main process without any installed tooling.

Limitation: access requires sufficient privileges. Other processes are readable only as root or with the same UID.

## Listening sockets without ss or netstat

Open and listening connections are exposed under `/proc/net/tcp` and `/proc/net/tcp6`.

```bash
cat /proc/net/tcp
```

The `local_address` column holds IP and port in hexadecimal. State `0A` marks a listening socket. The inode column links the socket to a process via `/proc/<pid>/fd`.

Limitation: the hexadecimal encoding requires manual conversion. Without `ss` or `netstat` the output is less readable.

## Inspect resolver configuration

The nameservers and search domains used for DNS resolution live in `/etc/resolv.conf`.

```bash
cat /etc/resolv.conf
```

The file shows `nameserver` entries, `search` domains and `options`. In Kubernetes it is generated by the kubelet based on the pod's `dnsPolicy` and points to the cluster DNS service.

## Recursive globbing in Bash

`shopt -s globstar` enables `**` as a recursive pattern across directory trees.

```bash
shopt -s globstar
ls **/*.log
```

Without `find`, this lists files across all subdirectories. A single `echo **` lists the whole tree as a flat alternative to `tree`.

Limitation: `globstar` exists from Bash 4.0 onward. It is absent in older Bash versions and in POSIX `sh`.

## Attach an ephemeral debug container to a pod

When a container lacks every tool, `kubectl debug` attaches an ephemeral container with a full-featured image to a running pod.

```bash
kubectl debug -it pod/app --image=nicolaka/netshoot --target=app
```

`--target` shares the process namespace of the target container, so its processes and network are visible. The ephemeral container uses an image with all tools, without altering the original image.

Limitation: ephemeral containers are GA since Kubernetes 1.25. `--target` requires the container runtime to support process namespace sharing.

## Node debugging with kubectl debug

To inspect a node, `kubectl debug` starts a pod that mounts the node's filesystem.

```bash
kubectl debug node/node-1 -it --image=nicolaka/netshoot
```

The debug pod runs in the node's host namespace; its root filesystem is mounted under `/host`. This inspects the node's logs, configuration and processes without entering it over SSH.

Limitation: the call requires permission to create privileged pods on the node.

## Summary

- `command -v` checks as a builtin which tools are present
- `getent hosts` resolves DNS through glibc, but is absent under musl and BusyBox
- `/dev/tcp/host/port` replaces a port check, available only in Bash
- `/proc/<pid>/environ` shows a process's environment
- `/proc/net/tcp` lists listening sockets without `ss` or `netstat`
- `/etc/resolv.conf` shows nameservers and search domains
- `shopt -s globstar` enables recursive `**` from Bash 4.0
- `kubectl debug` attaches an ephemeral container to a pod, GA since 1.25
- `kubectl debug node/<name>` inspects a node through a full-featured image
